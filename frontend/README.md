# Интерфейс Flowbridge

React + TypeScript + Vite, без отдельного Node backend. Локально Vite направляет `/api` к `http://127.0.0.1:8000`; в поставке собирается `dist/`. Шрифты Inter размещаются вместе со сборкой, внешнего CDN нет.

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Открыть [публичную страницу](http://127.0.0.1:5173), [демонстрацию](http://127.0.0.1:5173/#/demo) или [кабинет](http://127.0.0.1:5173/#/app). Ссылка на карточку: `/#/app/leads/{id}`. Backend и demo PostgreSQL запускаются по корневому README. Доступ к кабинету всегда требует оператора.

```powershell
npm.cmd run build
npm.cmd run lint
npm.cmd test
```

Браузерные проверки используют уже установленный Microsoft Edge в отдельном headless-профиле; установка системного браузера не выполняется. Для другого доступного Chromium задайте `PLAYWRIGHT_CHANNEL` или измените локальную конфигурацию. Первым должно быть запущено приложение в режиме `demo`, адрес меняется через `UI_BASE_URL`.

```powershell
$env:DEMO_OPERATOR_FILE = 'C:\путь\к\локальному\demo-operator.json'
npm.cmd run test:browser
```

Формат приватного файла: JSON с полями `email` и `password` синтетического оператора. Не добавляйте его в репозиторий. Скрипт не печатает пароль; трассировки отключены. Без файла тесты входа пропускаются и не считаются проверенными.

`tests/browser.spec.ts` проверяет настоящий локальный API и PostgreSQL: форму, ответ 202, защищённый кабинет, readonly demo и выход. Создаёт только синтетические заявки на зарезервированном домене `example.com`. Он требует `mode=demo` и не проверяет внешние провайдеры. `tests/ui-contract.spec.ts` отдельно проверяет состояния интерфейса на явно заданных HTTP-фикстурах: другой бизнес-конфиг, ошибки, загрузку, пустой список и инертное отображение HTML. Эти фикстуры не доказывают исправность backend.

Playwright сохраняет реальные снимки страниц в `test-results/`. Для desktop используется 1440×1000, для mobile — 390×844 с reduced motion. Версии зависимостей фиксированы в `package.json` и `package-lock.json`. Ключи не помещаются в `VITE_*`, localStorage или frontend-код.

Отдельный полный smoke требует запущенных PostgreSQL, backend, worker и опубликованных workflows n8n. Он проверяет `mode=demo`, создаёт синтетическую заявку, ждёт анализа, редактирует черновик, одобряет версию 2 и проверяет принятие **fake**-провайдером. Реальные OpenAI/SMTP/Telegram этим не проверяются.

```powershell
npm.cmd run test:processing
```

Результаты и снимки этого отдельного сценария находятся в `test-results-processing/`.
