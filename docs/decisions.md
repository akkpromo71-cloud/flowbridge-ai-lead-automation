# Утверждённые решения

Проект: одна компания на развёртывание; FastAPI + PostgreSQL + React/TypeScript/Vite + n8n.
Приоритеты: безопасность → корректность → восстановимость → понятность → бизнес-сценарий → визуальное качество.

## Уточнения пользователя
- `service_fit`: fit / not_fit / unknown отдельно от `service_id`; взаимная согласованность обязательна.
- Scoring использует только структурированные признаки с evidence. Не разбирает summary повторно.
- Бюджетный диапазон, пересекающий порог, и валюта без настроенного порога дают нейтральный вклад с объяснением.
- Незавершённый шаг атомарно захватывается в БД до внешнего вызова. Повтор видит running, а не запускает второе действие.
- Поздний webhook ACK не может откатить running/succeeded в dispatched.
- Публичное demo только для чтения синтетических данных; интерактивное — через защищённый кабинет. Авторизация не отключается в demo.
- Начать с установленного Python 3.12.10; смена runtime только при конкретной необходимости.

## Границы гарантий
PostgreSQL транзакционно сохраняет заявку и необходимость её обработки. Доставка webhook как минимум однократная с дедупликацией доменных шагов.
Сетевые вызовы выполняются вне транзакций. Generation/token защищают применение устаревшего результата, но не отменяют уже начатый внешний запрос.
После возможного SMTP-принятия и неопределённого результата — delivery_unknown, ручная сверка, без слепого resend.
Ответ, сохранённый до финального send gate, отменяет follow-up. Внешние IMAP и SMTP не имеют общей атомарной транзакции.

## Этапы
1. Конфигурация, PostgreSQL/миграции, оператор/сессии, intake/idempotency.
2. Задания/атомарные шаги, n8n, AI-schema/adapters, scoring/recovery.
3. Защищённый кабинет, история, версии/approval.
4. Telegram, SMTP/IMAP, один follow-up.
5. Продуктовые экраны, read-only demo, аналитика, два бизнес-конфига.
6. Воспроизводимая поставка, smoke/E2E, backup/restore, обучение и пилотный checklist.
