# Защита тестовой PostgreSQL

Интеграционные тесты удаляют записи между сценариями. Единственный разрешённый адрес для этих фикстур — `127.0.0.1:15432`, база `ai_leads_test`, драйвер `postgresql+psycopg`. Имя пользователя должно быть указано. Адрес `localhost`, другой порт, другая база, параметры URL и одного лишь окончания `_test` недостаточно для допуска.

Настройка обязательна и берётся только из переменной процесса `TEST_DATABASE_URL`, без значения по умолчанию и без загрузки `.env` защитным модулем:

```powershell
$env:TEST_DATABASE_URL = 'postgresql+psycopg://ai_leads_test@127.0.0.1:15432/ai_leads_test'
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

Запускайте команды из корня проекта при работающей локальной тестовой PostgreSQL. Не запускайте два набора интеграционных тестов одновременно: каждый сценарий очищает общие тестовые таблицы. Команда не предназначена для демонстрационной или рабочей базы.

`backend/tests/db_safety.py` сначала проверяет адрес без подключения. Затем `backend/tests/conftest.py` сверяет на реальном соединении `current_database()`, `inet_server_addr()` и `inet_server_port()`. При отсутствии настройки, несовпадении или невозможности проверки выполнение прекращается до изменения данных. Сообщения защитного модуля не содержат переданного URL, пароля или ответа сервера.

Миграция использует то же проверенное соединение через `Config.attributes['connection']`; поддержку переданного соединения обеспечивает `backend/migrations/env.py`. Перед каждым `TRUNCATE` фактическая база проверяется повторно на соединении той же транзакции. Обычные самостоятельные команды Alembic вне тестовых фикстур используют свой прежний механизм настройки; эта защита относится именно к запуску тестов.

Проверки отказа можно запускать без PostgreSQL и без `TEST_DATABASE_URL`:

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests/test_db_safety.py -q
```

В этом файле конструктор базы, соединения и миграции полностью заменены заглушками. Отрицательные сценарии не подключаются к посторонним адресам и не очищают базы. Сценарии проверяют также отсутствие вызова миграции/очистки после отказа и повторную проверку перед следующим очищением.
