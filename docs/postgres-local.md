# PostgreSQL для локальных demo и integration tests

**VERIFIED — 26.09.2026:** PostgreSQL **17.11**, Windows x64, portable EDB package revision **4**. Системный установщик не запускался. Служба Windows, системный PATH и правила firewall не менялись.

Исполняемые файлы находятся в `.local/postgresql-17.11-4/pgsql/`, исходный ZIP — в `.local/downloads/`. Скрипт извлекает только `bin`, `lib`, `share` и лицензионные файлы; pgAdmin и StackBuilder не нужны.

Кластер с синтетическими данными и журнал находятся **вне OneDrive**:

```text
%LOCALAPPDATA%\AILeadAutomationPro\postgres-17-demo-test\
  project-owner.json
  data\
  postgres.log
```

`project-owner.json` привязывает каталог к абсолютному пути проекта. Скрипты отказываются использовать существующий каталог без этого маркера или с другим владельцем. Они не удаляют данные. При перемещении проекта потребуется осознанно перенести локальное окружение; автоматического присвоения чужого каталога нет.

## Запуск и остановка

В PowerShell из корня проекта:

```powershell
.\scripts\start-postgres.ps1
```

При первом запуске скрипт скачивает зафиксированный архив с EDB, проверяет SHA-256, распаковывает локальные зависимости, создаёт кластер, две прикладные БД и отдельную служебную БД n8n. При последующих запусках сохраняет данные, проверяет работающий кластер и подключения. Свободный порт проверяется перед запуском; чужой процесс не останавливается. Окно фонового процесса скрыто.

```powershell
.\scripts\stop-postgres.ps1
```

Остановка выполняется через `pg_ctl -m fast`: активные транзакции откатываются, данные остаются на диске. Сначала завершите API, worker и тесты. База не зарегистрирована как служба и после перезагрузки Windows сама не запускается.

## Подключение

| Назначение | Сервер | База | Роль |
|---|---|---|---|
| Синтетическая демонстрация | `127.0.0.1:15432` | `ai_leads_demo` | `ai_leads_demo` |
| Интеграционные тесты | `127.0.0.1:15432` | `ai_leads_test` | `ai_leads_test` |
| Служебное состояние n8n | `127.0.0.1:15432` | `ai_leads_n8n` | `ai_leads_n8n` |

Для SQLAlchemy/psycopg:

```text
postgresql+psycopg://ai_leads_demo@127.0.0.1:15432/ai_leads_demo
postgresql+psycopg://ai_leads_test@127.0.0.1:15432/ai_leads_test
```

Роли приложения не имеют `SUPERUSER`, `CREATEDB`, `CREATEROLE` или `REPLICATION`. Каждая владеет своей БД. PostgreSQL слушает только **127.0.0.1**; `pg_hba.conf` разрешает каждой прикладной роли только соответствующую БД. Административная роль `ai_leads_admin` нужна только для локального создания БД.

Это намеренно ограниченная **синтетическая demo/test-конфигурация** с локальным `trust`, без пароля и TLS. Любой процесс на этом компьютере, знающий локальную административную роль, может подключиться к этому кластеру. В него нельзя помещать реальные клиентские данные или live-секреты. Для live требуется отдельно настроенный сервер с паролями/секретами, ограниченным доступом и резервным копированием. Настройки `trust` переносить в live нельзя.

Часовой пояс SQL-сессий — UTC, кодировка — UTF-8. Журналы находятся вне репозитория; логирование SQL statements отключено. Миграции приложения выполняются отдельно командой из основного README.
