# Коммерческая демонстрация за 3–5 минут

Подготовка: `scripts/start-dev.ps1`, уникальный demo-оператор, синтетический HOT-пример из public demo. Нельзя использовать реальные адреса или выдавать симуляцию за live. Весь экран содержит только demo-данные.

| Время | Действие | Что объяснить владельцу бизнеса |
|---|---|---|
| 0:00–0:25 | Landing → public demo | «Система помогает разобрать обращения и подготовить ответ. Решение об отправке остаётся у вашей команды». |
| 0:25–0:55 | Login → новая тестовая заявка | «Форма сохраняет обращение и ставит обработку в очередь; повторная отправка не создаёт дубль». |
| 0:55–1:30 | Processing → карточка анализа | «Вот подтверждённые цитатами факты, неизвестные поля и score по критериям. Сейчас AI-провайдер SIMULATED; отдельные результаты настоящего OpenAI доступны в отчётах». |
| 1:30–1:55 | Dashboard → HOT → история уведомления | «Менеджер получает приоритет и ссылку в защищённый кабинет. Telegram в demo симулирован». |
| 1:55–2:45 | Draft → edit → новая версия → approval | «Это предложенный текст. В demo он детерминированный; отдельный real LLM draft VERIFIED controlled ($0.000626), human approval required, sent=false; новая версия prompt проверена только бесплатно. Правка снимает одобрение. Сейчас одобряем только эту точную версию». |
| 2:45–3:10 | Simulated send → history | «Принято fake-провайдером. Это не реальная отправка и не подтверждение доставки». |
| 3:10–3:35 | Follow-up → reply/opt-out | «Один follow-up после acceptance, с отдельным одобрением. Ответ или stop отменяют его. Без свежего inbox нужна ручная проверка». |
| 3:35–4:00 | Analytics → integrations | «Метрики считаются из событий этой demo-базы за указанный период. Они не доказывают экономию или рост прибыли». |
| 4:00–4:30 | Pilot checklist | «Для вашей компании согласуем услуги, правила, test mailbox, качество модели, расходы и восстановление. Затем проведём ограниченный пилот». |

Для ответа demo-клиента после fake acceptance:

```powershell
.\.venv\Scripts\python.exe -m app.cli demo-reply --lead-id <UUID>
```

Follow-up delay обычно 48 ч; для быстрой демонстрации используйте отдельно настроенный demo-конфиг и fixture-controlled clock в тестах. Не переводите часы Windows и не меняйте даты рабочих заявок. Автоматизированный полный сценарий reply/follow-up подтверждается PostgreSQL-тестами; browser processing smoke показывает intake→draft→edit→approval→fake acceptance.
