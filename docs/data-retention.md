# Хранение и удаление данных

Политика v1 для пилота задаётся владельцем компании до внесения реальных данных. Стартовое предложение: заявки и переписка — 90 дней после закрытия, служебные журналы без текстов — 14 дней, резервные копии — 30 дней. Это эксплуатационные значения для согласования, а не правовая рекомендация. Автоматический планировщик удаления в v1 отсутствует; назначается ответственный за еженедельную проверку.

## Удаление одной заявки

Утилита предназначена для администратора сервера в окно обслуживания. Установить запрет на входящие запросы, остановить API, worker и расписания отдельного project n8n; дождаться завершения сетевых операций. Не останавливать чужой n8n. Активные задания и состояние `sending` блокируют удаление даже после остановки процессов; сначала требуется штатное восстановление и выяснение результата отправки.

Посмотреть состав удаления без изменения данных:

```powershell
.venv/Scripts/python.exe -m app.retention --lead-id <UUID>
```

После отдельного разрешения владельца данных подтвердить точный номер заявки из preview:

```powershell
.venv/Scripts/python.exe -m app.retention --lead-id <UUID> --confirm-reference <REFERENCE>
```

Удаляются заявка, её анализы, версии писем, решения, задания, шаги и связанная история через каскады PostgreSQL. Остаётся только событие удаления со счётчиками, без исходного идентификатора и персональных полей. Неверное подтверждение ничего не меняет. Нет массового HTTP endpoint и автоматического обхода ошибок ограничений БД. Чужая связанная переписка не удаляется ради обхода foreign key.

Ограничения: несопоставленные входящие письма ещё не связаны с заявкой; их требуется отдельно найти и удалить в контролируемой транзакции администратором. Запись opt-out в `recipient_suppressions` сохраняется, чтобы удаление заявки не разрешило новую отправку тому же адресу. Основание и срок хранения этого минимального адресного списка согласуются отдельно. Почтовый сервер, Telegram, экспортированные файлы, данные провайдера AI и резервные копии не очищаются этой утилитой.

## Резервные копии и журналы

Для live требуется отдельное защищённое хранилище с шифрованием, доступом только оператора резервирования и автоматическим истечением 30 дней либо согласованным сроком. Демонстрационный `scripts/check-restore.py` создаёт проверочную копию, но не устанавливает расписание и не удаляет старые копии. Его локальные копии расположены в `%LOCALAPPDATA%/AILeadAutomationPro/backups`, за их очистку отвечает оператор.

При восстановлении старой копии повторно применить реестр согласованных удалений до открытия доступа. Не включать удалённые данные в новые демонстрации. Резервировать отдельно базу n8n и его ключ шифрования; без ключа credentials могут стать непригодными.

В поставляемых workflows история executions не сохраняет успешные, ошибочные и ручные payloads; бизнес-история хранится в PostgreSQL приложения. Локальные `.local/*.log` не должны передаваться публично без проверки. Настройка внешней ротации и хранения журналов выполняется перед пилотом.
